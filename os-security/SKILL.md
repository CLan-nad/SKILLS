# OS Security — 操作系统黑盒漏洞挖掘

**产出**：`<目标名>/vuln-00N/`，内含 `report.md` + `poc.py`（Python 优先；仅单条命令可证时才用 `poc.sh`）。编号从 `vuln-001` 递增、目录名与报告编号一致；越权与信息暴露**统一编号，仅以危害等级区分**。未发现漏洞 / 目标不可运行也要给结论。

---

## 一、判定：什么算漏洞

- **主判据**：普通用户能否通过 SUID/Cap/D-Bus/PolicyKit/配置执行**原本需要 root** 的操作；或（扩展模式下）**跨信任边界**造成危害。
- **什么不算**（任一满足即停）：
  1. 设计意图——该操作本为普通用户设计
  2. 默认权限——普通用户不依赖提权机制即可执行
  3. 操作拦截——执行失败或**完全无实质意义**（注意：**未授权读取 / 只读访问本身即危害**，内容为空或读不出数据不影响成立）
  4. 策略正确——Polkit 默认 action 配的是 `auth_admin`
  5. 开源一致——**经 diff 上游 / 查厂商补丁确认未修改**才跳过（厂商打过补丁的按自研对待）
- **危害原则**：**仅真正系统级不可逆 / 中断性动作不执行**（reboot/shutdown、系统还原/回滚、磁盘格式化/擦除、不可逆数据销毁）；**其余一律实测并报告，含进程级 DoS（kill/崩溃服务）**。基线/对照一律**非交互**（勿用会弹密码的命令）。
- **Polkit 专项**：**默认放行且最终落到特权操作**的 action = 漏洞（`modify.system=yes`；自定义 action `allow_any=yes` 且 `exec.path` 指向特权程序/行为）；`modify.own=yes`（仅改自身设置）= 正常设计。
- **信息泄露**：先以普通用户直接试读，再按内容三分类——**A 设计公开**（非漏洞，但须写一行"已评估"）／**B 敏感过度开放**（独立低危编号）／**C 使能器**（按 B 编号并交叉引用所使能的漏洞）。**不得因"world-readable"静默丢弃**（细则 → report-template.md）。
- **扩展模式**（插拔，默认关闭）：先测完全部特权面；若攻击面**全落在登录用户权限域内** → **停止并询问用户**（①进入扩展 ②停止〔默认〕 ③仅记录；答复=**本次会话开关**，结论头部注明口径）。扩展门槛 = 跨信任边界（不可信输入 → 受害者上下文危害；同 UID 域任意进程可调且造成破坏）。**同权限域下 `C/I/A` 不得取 H**，一律标注"不可越权"（细则 → report-template.md）。
- **优先级**：自研组件 > 开源组件（kydima / ksaf / ukui / kysec / 三权分立相关优先深挖）。

## 二、主流程【唯一权威】

**起点**：给的是**组件名 / 包名** → 从第 0 步起走全流程（先把它梳理成攻击面清单）；直接给的是**某个攻击面**（二进制路径 / D-Bus 服务名 / PolicyKit action / 配置文件路径）→ 跳过第 1 步，从第 2 步起。

0. **基线**　非交互权限对照（`pkcheck --action-id <id> --process $$` rc=2 / `login1 CanReboot` / 自建文件属主对照）；锁定**审计边界**（`readlink /proc/PID/exe`→`dpkg -S`；策略文件是否以组件名命名；归属外实体只记"关联观察"）；**执行组件**（`.service`→start，`.ko`→modprobe——不运行=白测）。
   **出口**：目标可运行；不可运行 → 记原因、只测静态项。→ component-discovery.md
1. **攻击面梳理**　把组件展开成**攻击面清单**：文件（二进制 / 配置）、进程、D-Bus 服务、PolicyKit action、内核模块、socket……；逐面确认是否适用（不适用写一行原因）；做权限摸底与启服前后 diff（含数据目录）。
   **出口**：清单成型，每面有"测 / 跳过+原因"；无"根路径空即放弃"。→ component-discovery.md（门禁检查表 / A1–A3）
2. **定级**　对每个攻击面的**接口 / 方法 / 可控入口**按危险度排序，危险面先测；不认识的术语先搜 Linux 背景。
   **出口**：危险面排在最前。（无固定参考——通用判断）
3. **挖掘 ★**　以普通用户**逐个执行对应操作**；**字符串实参直接用注入载荷**（调用即注入——一次调用同时回答"是否未授权"与"是否注入"）。**有专门 reference 的攻击面就按它深挖，没有的用通用手法**（枚举入口 → 逐个调用 → 观察返回 / 副作用）：
   - **SUID / Cap 二进制文件** → `suid-analysis.md`、`cap-analysis.md`（文件类先做 **argv 参数首扫**，先于一切静态分析）
   - **D-Bus 服务**（含 P2P / 抽象套接字）→ `dbus-authz.md`
   - **PolicyKit action** → `polkit-authz.md`
   - **可写文件 / 配置 / socket / 内核模块 / 进程** → `component-discovery.md`（配置审计 / socket 审计 / 模块参数 / 状态 diff）

   **出口**：无鉴权即记漏洞；每入口记录返回分层；AccessDenied=被拦→换面；**声明≠可调用**（声明存在但 `UnknownMethod` 要标注）。
4. **载荷未生效则换形重试**　按被拼模板的**引号形态**：`'` 逃逸 / `$( )` / 反引号 / `${IFS}` / 换行。
   **出口**："无注入"须证**载荷已到达执行点**（前置失败 = inconclusive，须补齐前置重测）。
5. **系统级验证**　marker + owner uid / 状态变化 / `strace -f -e trace=execve`；**不依赖接口返回值**。
   **出口**："方法可调用"与"影响已证实"**分开取证**。→ inj_sweep.py
6. **静态解释（可选）**　仅限 (a) 轻量根因解释 / (b) 疑似高危入口利用失败；只定位，**不做全面反汇编·函数边界·变量追踪**。
   **出口**：黑盒一旦给出答案即停。→ suid-analysis.md「可达性回溯」
7. **深入利用**　确认漏洞后逐面放大危害：任意文件写 → sudoers / cron / SSH key / systemd、路径穿越、符号链接、提权链。
   **出口**：每漏洞落到**最大可证明危害**。→ exploit-patterns.md
8. **交付**　PoC（末行三态结论）→ 报告 → 收尾清理。
   **出口**：PoC 实机跑通、收尾清理已跑。→ poc-template.py、report-template.md

## 三、红线

- **次序门禁**：**未完成一轮未授权调用（含注入载荷实参）前，禁止进入反汇编**。开反汇编前先做**输入形状枚举**（文件/目录、扩展名、内容、嵌套层级）。
- **判定靠黑盒**：是否注入、是否经 shell，以 marker + owner uid 为准；逆向（objdump/nm/strings）只用于**定位**，不用于判定。
- **不做全面反汇编 / 函数边界分析 / 变量追踪**（仅主流程第 6 步的 (a)/(b) 两例外）。
  > **例外**：组件由**可读脚本/配置**（`.py`/`.sh`/`.conf`）定义时，通读其源文件属「枚举」范畴，不受本条限制。
- **不跨汇点外推**：一个汇点的调用方式不能外推到另一个汇点。
- **反模式**：不得以未验证的假设终止探测（"不可达 / 非漏洞"须有系统级证据）；**禁止**用 `grep 'call.*<sink>'` 只找到一处就判不可达；**禁止**把"载荷未执行"当"不会执行"（前置失败 = inconclusive，须补齐前置重测）。
- **止损线**：探测已能支撑结论即停止静态逆向；安全机制（白名单/Polkit/KYSEC 等）的内部算法不深挖——现象足以定位根因即可，余者写入报告「进一步分析建议」。**判"绕过"之前先核验机制确已加载生效**（→ dbus-authz.md / polkit-authz.md）。

## 四、交付

- **PoC**（骨架 → `poc-template.py`）：Python 优先、`step()` 彩色输出；**默认四阶段** 1 Presence／2 Reachability／3 Impact／4 Cleanup（可合并，但**编号不得跳号**）；**末行三态结论**（`漏洞存在` / `漏洞不存在` / `poc 执行失败，请调整环境或改用其他方式验证`，退出码 0/1/2）；**交付前必须实机跑通**（进程未运行须 `ensure_process()` 幂等自拉起）；**`finally` 自清理**（还原配置、删标记，报告须给清理回显）。基线**非交互**且与 Impact **同族**；批量注入探测可用 `inj_sweep.py`。
- **报告**（模板 → `report-template.md`）：首句陈述句 `<组件> 存在 <漏洞类型> 漏洞`（不加粗、不举例、不写具体组件名）；CVSS 3.1 写"向量 + 一行依据"且**必须经 `cvss31_calc.py` 复核**；含四阶段「验证情况」；结论先行、不堆细节。
- **收尾清理**（每次必跑）：① 枚举本次变更（拉起/激活的进程与服务、root 属主产物 `find /tmp /run -user root -newermt '<开始时间>'`、改过的配置、`/tmp/inj_*`）；② 尽力还原（停本次拉起的服务、还原配置、删临时文件）；③ **无法还原的列清单交操作者**（附一行 sudo 命令）。
- **覆盖小结**：结论尾部写 N/M 攻击面已测、X 跳过及原因。
